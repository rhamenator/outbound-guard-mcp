# Current egress threat model

This document maps the **implemented** stdio `guarded_fetch` GET/HEAD boundary to its tests. It describes the experimental `main` branch as of 2026-10-21. [QUALITY_BAR.md](QUALITY_BAR.md) is the stable-release acceptance list; an entry here is not a waiver of an open gate.

## Assets and boundaries

- The operator's approved host list, local network, metadata services, secrets in the agent context, agent time and memory, and content the model may trust are at risk.
- An autonomous agent supplies tool arguments. An external host, its DNS answers, TLS endpoint, headers, redirects, and body are untrusted. Local proxy variables may be hostile or accidental. A caller may send malformed or oversized MCP frames.
- The enforcement boundary is one `tools/call` to this server. The server cannot see or govern traffic sent through a browser, shell, another MCP server, or any other agent tool. The companion skill can guide tool choice but cannot enforce it.
- A valid MCP call passes from `src/main.rs::handle` to `src/lib.rs::guarded_fetch`. Validation and reservation run before DNS, then a pinned HTTP client connects, and the response is bounded before any `body_text` is returned. A blocked call returns stable `rule` and `remediation` fields; it does not return a partial body.

## Implemented controls and evidence

| Threat | Current code path | Reproducible evidence and limit |
| --- | --- | --- |
| SSRF through literals, private IPs, mixed DNS answers, or ambiguous URLs | `validate_with_reservation`, `valid_dns_name`, `public_ip`, `public_v4`, `public_v6` in `src/lib.rs` | `tools/netns_adversarial_probe.py` denies private/mixed IPv4 and IPv6 answers before any HTTP hit. `special_use_prefix_boundaries_stay_denied` samples the first, last, and interior addresses of 15 IPv4 and 12 IPv6 denied prefixes informed by the [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry), [IPv6](https://www.iana.org/assignments/iana-ipv6-special-registry), and [multicast](https://www.iana.org/assignments/multicast-addresses) registries. This finite matrix does not replace URL/IP property or fuzz tests. |
| DNS rebinding between calls or DNS substitution after validation | `SystemResolver` and `guarded_fetch` use validated socket addresses directly, with the original Host/SNI name | The route-free probe denies a 20-answer DNS set before HTTP and changes an A answer between two calls in one MCP process; the second is denied with no second HTTP hit. SNI is observed as the original hostname. The retained DNS iterator is capped at 17 entries, but OS resolver allocation before iteration is not application-bounded. Reconnect within one call remains unproven. A separate same-CA fixture proves the TLS hostname mismatch case. |
| TLS trust and hostname mismatch | `EXTRA_CA`, `validate_tls_configuration`, and `guarded_fetch_inner` in `src/lib.rs` | The operator may add one bounded PEM certificate at startup. A matching SAN signed by the fixture CA succeeds; a mismatched SAN signed by the same trusted CA fails before HTTP. The matching certificate fails when the CA option is absent. All cases preserve original-host SNI. Ten invalid CA configurations stop startup without echoing content or paths. The operator must control the trust file; changes require restart. This does not certify every TLS configuration. |
| Ambient proxy or credential forwarding | direct pinned TCP/TLS connections without proxy/environment lookup, no custom header/body fields in `validate_with_reservation` | The route-free probe sets dead `HTTP_PROXY` and `ALL_PROXY` values yet reaches the pinned fixture. The schema rejects unknown fields. This does not govern credentials or traffic from other tools. |
| URL secret exfiltration | `has_known_secret` and `high_entropy_segment` before `reserve_egress_call` and DNS | Six synthetic URL markers are denied before DNS/HTTP and absent from MCP output and stderr in the route-free probe. Detection is heuristic, incomplete, and limited to accepted URL input. Header/body exfiltration is not supported by this tool and has not been adversarially certified. |
| Recursive, cross-host, or private redirect traps | One explicit HTTP/1 request in `transport::send`; `guarded_http_fetch` rejects redirection statuses | The route-free probe denies a redirect to private space, a self-loop, and a second approved host without following or resolving the destination. Redirect revalidation and atomic multi-hop budgeting are not implemented. |
| Slow first byte, byte drip, or late EOF | Three-second connect/TLS timeout and `BudgetIo` read deadline in `transport::send`; pinned `HTTP_TOTAL_TIMEOUT` future in `guarded_fetch_inner` | Controlled delayed-header, one-byte-per-second, and late-EOF fixtures deny without partial body. A fixed four-bucket transfer-rate counter now checks the preceding three completed seconds after a three-second body grace period, denying averages below 500 bytes/second. Slow-drip and burst-then-drip fixtures deny without partial text; a 600-byte/second control passes. Rate checks await body reads, so the read timeout can delay rate classification; the independent async total timer interrupts reads at the total deadline. Legitimate slow endpoints may be rejected. |
| Oversized, encoded, or malformed HTTP responses | Header count/byte checks, framing checks, encoding denial, and bounded read loop in `guarded_fetch` | The route-free probe covers 70 headers, a 24 KiB header, a 1 MiB parser header, conflicting framing, duplicate Content-Type and Content-Encoding fields, stacked or duplicate Transfer-Encoding fields, chunked overflow, invalid chunk sizes, truncated chunks, and gzip/deflate bombs. The malformed chunk probes confirm no partial body is returned, but do not exhaust parser inputs. Hyper is configured with a 64-field/16 KiB parser buffer; budgeted HTTP I/O caps stream bytes to return limit plus 32 KiB, with separate 1 MiB/64 KiB underlying stream read/write caps. Serialized request size is checked before DNS. Trailers are denied. GET now accepts only a bare supported media type or one UTF-8 charset parameter; ten socket-level MIME cases test malformed/conflicting/unknown parameter denials and valid controls. This is a narrow allow policy, not a general MIME parser. Encoded responses are refused rather than decoded, so no accepted compressed expansion is performed. Application stream-byte caps are implemented; packet/kernel-buffer accounting, decompression support with expansion-ratio caps, and aggregate resource bounds across processes are not. |
| Hidden HTML links or indirect prompt injection | `supported_content_type` rejects declared HTML; `looks_like_html` blocks leading HTML signatures mislabeled as plain text; allowed responses set `untrusted_content: true` | The route-free probe denies declared HTML, a fake media type, and a leading hidden-link fragment labeled `text/plain`. It also denies HTML mislabeled as JSON, incomplete JSON, trailing garbage, excessive nesting, and an empty 200 JSON response. Empty no-content responses remain accepted. Valid JSON instruction-like text and HTML string values are returned unchanged; this is syntax validation, not schema validation or sanitization. Prefixes and unrecognized tags can bypass the narrow HTML check; the marker does not sanitize or quarantine prompt injection. |
| MCP frame exhaustion and malformed RPC | `read_frame` and `handle_cancellable` in `src/main.rs` | `tools/stdio_resource_probe.py` streams 160 MiB and 8 MiB hostile frames, checks bounded RSS and ping recovery. `tools/adversarial_stdio_probe.py` checks malformed messages and no secret echo. A ten-second ingestion deadline starts at the first observed bytes; stalled and continuously fed unterminated frames are tested for process termination, no partial dispatch or marker echo, and idle-client survival. Checks occur per chunk and while the dispatcher waits; executing fetches can delay observation. Replies have a separate three-second write/flush acknowledgement deadline, tested with an unread 4 KiB stdout pipe; expiry terminates the process and may leave a partial transport frame. This is not a CPU quota; full protocol and cancellation conformance remain open. |
| Excessive calls to one host | `CallBudget::reserve` and `reserve_egress_call` | Unit tests cover window arithmetic. The route-free MCP probe proves per-host 60/61 with mixed-case hosts and failed HTTP responses, failed-DNS 60/61, and process-hour 1000/1001 across 17 hosts. A/AAAA-query and HTTP-hit counts show each rate denial occurs before DNS and HTTP. Restart resets the budget. Live expiry, concurrent clients, and multi-process budget behavior remain unproven. |

## Client and release evidence

The process-local audit resource `outbound-guard://logs/audit.json` retains at most 256 completed decisions using a field whitelist (correlation ID, status, rule). `tools/adversarial_stdio_probe.py` checks 300 real MCP blocked calls for correlation, retention, eviction, and absence of synthetic tokens in results and stderr; a unit test also verifies that allowed-response URLs and body text are excluded. The official Inspector smoke checks resource discovery and reading. IDs are process-local, and restart loses all events. This is diagnostic evidence, without persistent storage, timestamps, subscriptions, or tamper resistance. Any client of the process can read the resource. Protocol failures and other tools are outside this log.

The [Codex CLI](client-codex-cli.md) and [Claude Code](client-claude-code.md) smoke tests demonstrate real client discovery, a blocked call, and approved GET/HEAD. [Inspector](../tools/inspector_smoke.py) and the [isolated socket probe](adversarial-netns.md) cover protocol and hostile fixture slices. No test here proves whole-agent egress coverage.

The initial unsigned Cursor attempt was inconclusive, but subsequent authenticated Cursor ACP discovery, denial, GET and HEAD calls passed against controlled fixtures. See the dated [real-client cancellation evidence](client-cancellation.md): the tested Codex/Cursor control paths did not send wire cancellation; terminal/desktop UI coverage and final-candidate repeats remain open. Do not treat earlier sign-in failures as the current client status, or successful calls as proof of prompt cancellation.

Remaining stable-release work includes final independent protocol/client review, native/OS resource limitations, broader secret handling/quarantine, broader property/coverage-guided fuzzing and human review under [QUALITY_BAR.md](QUALITY_BAR.md). Parser/stream bounds, bounded admission/cancellation, independent native rebuild comparison and signed trusted-main provenance now have specific tested evidence in the [release checklist](RELEASE_CHECKLIST.md); require those gates on the exact final candidate rather than transferring historical results.

The [candidate packaging gate](candidate-packaging.md) tests a local optimized Linux x86_64 artifact after extraction, including the isolated hostile fixtures and official Inspector. Its companion skill ZIP contains only the committed SKILL.md and GPL license. Checksums and provenance identify the tested bytes; cross-host reproducible compilation, signing, dependency attribution, and human release approval remain open.

The route-free schema mutation probe derives invalid argument families from the running tool declaration (required fields, types, bounds, enum, and unknown fields), applies 512 seeded mutations, and checks all 33 ASCII control bytes at three URL positions. One valid baseline request must reach the fixture; all 644 invalid inputs must return BLOCKED before any further A/AAAA query or HTTP hit. A synthetic marker in rejected inputs must be absent from stdout, stderr, and audit content. The seed and corpus SHA-256 identify the executed corpus. This exposed the leading-NUL URL normalization gap, now blocked in `validate_with_reservation`. This is bounded mutation testing, not exhaustive or coverage-guided fuzzing, and it does not close the IP, framing, or full protocol fuzz gates.

Each server process permits one active `guarded_fetch`, spanning validation, budget reservation, DNS, TLS, and response reading. Concurrent Rust library callers receive audited `EGRESS_CONCURRENCY_LIMIT` denials before budget reservation or network work; retry after the active call completes. Fetch execution remains sequential; one bounded input-reader thread can process cancellation notifications while a fetch is active. The limit does not coordinate separate processes or bound a client’s input queue. A completed or failed fetch releases the permit.

Concurrency regression evidence: `concurrent_fetches_fail_before_execution_and_release_after_failure` holds the production permit inside a controlled execution closure while 32 real threads attempt audited fetch admission. Every contender must be denied without executing its validation/network closure, and its denial must appear in its audit log. After an HTTP-failure result, a fresh call must execute. Debug unwind recovery is also tested; optimized builds abort on panic. This tests admission and permit cleanup, not concurrent socket behavior, cancellation, or a host-wide limit.

Generated address-policy evidence: [the CIDR integration corpus](ip-policy.md#generated-policy-regression-evidence) checks approximately 1.31 million deterministic address decisions and 288 mixed DNS answer sets, including forbidden answers after public answers. Two deliberate policy regressions were detected in mutation sanity checks. These are network-free policy checks; they do not replace the controlled socket probes or independently satisfy other repositories’ adversarial gates.

GitHub token URL coverage now includes `github_pat_`, `ghu_`, `ghs_`, and `ghr_` alongside `ghp_`/`gho_`. The [GitHub corpus](adversarial-netns.md#github-token-signatures) checks 13 synthetic blocked paths and eight allowed lookalikes, with pre-DNS/pre-HTTP denial and redacted MCP/audit output. Prefix plus a 20-character suffix is a conservative heuristic, not complete secret discovery or token validity checking.

Repeated-call resource evidence: the [isolated live-budget workloads](adversarial-netns.md#repeated-call-descriptor-and-memory-evidence) run each server process under an observed OS-enforced 64-file-descriptor limit, sample descriptor count and kernel RSS high-water, and require correct responses and audit retention below a 128 MiB RSS test threshold. This is finite workload evidence, not a production memory cap or host-wide resource policy.

MCP envelope metadata: [the stdio metadata regression](adversarial-stdio.md#mcp-parameter-and-metadata-regression) rejects malformed parameter/metadata shapes before dispatch, preserves correlation and handshake state, and proves no malformed tool audit entry or marker echo. This does not close the newer-revision, progress, or cancellation gates.

Cooperative library cancellation: `guarded_fetch_cancellable` observes a caller-owned atomic flag at validation/network/read/return boundaries and suppresses body output on observed cancellation. The [controlled consumer probe](adversarial-netns.md#cooperative-library-cancellation) checks an audited denial, peer-observed socket close and subsequent fetch recovery. DNS and HTTP waiters observe cancellation in 25 ms slices subject to scheduling, retaining their absolute deadlines. Native resolver work can outlive its waiter, and spent rate reservations remain counted. Stdio notification handling is tested separately below.

Stdio cancellation: the [wire cancellation cases](adversarial-netns.md#stdio-cancellation) exercise exact ID matching, malformed/late notification handling, reply suppression, audit redaction, peer socket cleanup and recovery. One bounded reader thread enables control handling during a fetch; ordinary queue saturation no longer blocks control admission. An incomplete input frame, client notification delivery and OS scheduling can still delay observation. This remains partial protocol/timing/client evidence, not an OS-level interrupt or complete conformance claim.

Provider-signature extension: the [GitLab/PyPI corpus](adversarial-netns.md#gitlab-and-pypi-token-signatures) adds 42 blocked synthetic paths and 28 allowed lookalikes, with no DNS/HTTP or marker echo for denials. Custom prefixes and other credential shapes remain gaps; the policy does not identify all secrets.

Mislabeled fragment-root evidence: [thirteen hidden-link fixtures](adversarial-netns.md#mislabeled-html-fragment-roots) cover common container/form/image/template roots with no body returned. Leading-signature matching remains a heuristic; unrecognized roots, nonleading markup, CSS visibility and arbitrary prompt injection remain outside this protection.

Exact-name resolution: [hostile search-suffix fixtures](adversarial-netns.md#absolute-dns-and-hostile-search-suffix) reproduce the pre-fix wrong-name lookup, then require zero suffixed DNS questions after absolute lookup enforcement. Private-answer rejection remained effective in the pre-fix case. System resolver/hosts data remains trusted operator configuration.

HEAD evidence: [controlled HEAD fixtures and official SDK](adversarial-netns.md#controlled-head-requests) check method preservation, empty-body results, header/framing policy, redirect refusal and first-byte timeout. HEAD success is independent of a future GET decision and does not assess representation content.

Credential isolation evidence: [six consecutive same-process requests](adversarial-netns.md#credential-isolation-across-calls) cover a same-host non-Secure response cookie, Basic challenge and four synthetic credential environment variables with no sensitive request headers, retries or marker echo. This is bounded evidence, not certification of every credential provider or authenticated-session support.


HTTP total-deadline evidence now uses cancellable async I/O and a stricter late-EOF fixture; see [the pending-read regression and remaining transport limits](adversarial-netns.md#hard-http-total-deadline). DNS is a separate phase budget. The subsequent bounded HTTP/1 transport now configures parser limits and counts HTTP/TLS stream bytes; see the stream-budget evidence below.


[Configured parser and stream-budget evidence](adversarial-netns.md#configured-http-parser-and-stream-budgets) covers header boundaries, excessive chunk framing, trailers and serialized-request preflight. These are application-stream caps, not bounds on kernel buffers, retransmissions, resolver allocations or CPU. Independent release gates and human review remain open.


Modern stateless stdio metadata/discovery and legacy compatibility are now exercised by [revision-specific wire and official-client checks](protocol-conformance.md). Historical modern refusal is not the current behavior. The client matrix and independent conformance/release review remain open; the transport is still stdio only.

[Seeded black-box framing mutation](adversarial-stdio.md#seeded-frame-mutation-and-recovery) adds 626 cases per era, recovery after each, empty audit and sampled resource bounds. It is finite property evidence; coverage-guided fuzzing and full protocol/client attack coverage remain open.

[Live OS DNS worker exhaustion](adversarial-netns.md#live-os-dns-worker-exhaustion-and-recovery) now verifies a real lookup outliving its three-second caller deadline, twenty busy denials without thread/query/socket multiplication, late-answer discard and successful recovery after release in both eras. Private namespace resolver configuration is inode-checked and restored. OS allocation/NSS cancellation and a permanently stuck resolver remain outside this finite proof.

DNS waiter cancellation uses 25 ms receive slices without extending its absolute deadline. Controlled live-DNS tests in both protocol eras require a subsequent ping within one second, cancellation audit and suppressed tool reply, retained single worker/busy denials, and recovery after release. Native resolver execution remains uncancellable; a client must send cancellation for this path to apply. See [DNS cancellation evidence](adversarial-netns.md#cooperative-dns-waiter-cancellation).

[Silent HTTP cancellation](adversarial-netns.md#cancellation-during-silent-http-waits) checks pending header and body waits with no arriving bytes, in both protocol modes. One pinned total-deadline future is polled through 25 ms timeout slices; cancellation drops the pending request/runtime. Existing total-time fixtures guard against inadvertently renewing the ten-second deadline. These finite plaintext cases do not certify every connect/TLS state or client notification path.

[Silent TLS handshake cancellation](adversarial-netns.md#cancellation-during-a-silent-tls-handshake) adds a real ClientHello/no-ServerHello case in both protocol eras. It requires prompt peer socket closure, suppressed reply, cancellation audit and subsequent successful ID reuse. This narrows the pending-TLS evidence gap; TCP SYN blackholes, every handshake state and native client controls remain outside that finite fixture.

[Independent syscall observation](adversarial-stdio.md#independent-syscall-observation-of-pre-dns-denials) traces twelve pre-DNS denials in each protocol era, with a positive tracer control and zero allowed network syscalls in the server process tree. It complements fixture hit counts without relying solely on returned decisions. This finite development probe is not an enforcement sandbox or proof of all traffic paths.

[Post-DNS syscall observation](adversarial-netns.md#post-dns-syscall-observation) independently checks eight real-DNS forbidden-answer cases per era with no extra Internet stream sockets, plus allowed TCP controls and redirect refusal. Decoded TCP destinations must be only the fixture on port80; DNS UDP/Unix operations remain distinct. This strengthens the selected post-DNS SSRF evidence without certifying every resolver or fallback path.
