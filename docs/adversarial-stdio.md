# Stdio resource probe

After `cargo build --locked`, run `python3 tools/stdio_resource_probe.py target/debug/outbound-guard-mcp` on Linux. CI runs the same probe. It streams a 160 MiB unterminated JSON-RPC frame in 1 MiB chunks followed by a valid ping, then streams another 8 MiB frame ending at EOF. Streaming keeps the probe parent's memory low so its fork does not contaminate child peak RSS. Both oversized frames must return a bounded protocol error; the ping must succeed after the first frame is drained. The probe checks the child process peak RSS stays under 128 MiB, allowing runtime and runner variation. A regression that buffers the entire 160 MiB frame would exceed that ceiling. The current host run records the measured RSS in its output.

This establishes bounded memory for those two large-frame cases and recovery after one malformed frame. The separate ingestion-deadline cases below cover stalled and continuously fed partial frames; this is not a CPU quota or a network concurrency test. The full resource and adversarial gates remain in [QUALITY_BAR.md](QUALITY_BAR.md).

## MCP parameter and metadata regression

The implemented 2025-06-18 [request/notification schema](https://modelcontextprotocol.io/specification/2025-06-18/schema#jsonrpcrequest) requires object parameters and object `_meta` when present. The dispatcher now rejects array parameters and malformed `_meta`/request `progressToken` values with correlated `-32602` errors, before tool execution. Malformed initialized-notification metadata is ignored without a reply or handshake advancement. Unknown metadata fields remain allowed, including arbitrary extension values; valid string and numeric progress tokens are accepted but do not enable progress notifications.

`tools/adversarial_stdio_probe.py` sends 24 malformed requests, three invalid initialized notifications, four valid metadata controls and an audit read. It verifies correlation, handshake state, absence of marker echo, and an empty audit (no malformed tool dispatched). Rust tests also cover initialize, resources/read and session preservation. The previous optimized candidate accepted invalid initialized metadata and failed the wire regression. The installed candidate packaging gate now runs the full stdio adversarial probe as well as Inspector and network fixtures. This is partial 2025-06-18 envelope validation, not full 2026-07-28, cancellation, or progress conformance.


## Framing boundaries and fragmentation

`cargo test --locked generated_frames_match_line_oracle_across_buffer_boundaries` runs a deterministic byte-stream property test with seed `0x6672616d696e6721`. An independent oracle splits the complete corpus at LF and classifies each complete slice by byte length; the production reader must return the same bytes or an oversized-frame result. Seven BufReader capacities (1, 2, 3, 7, 64, 8192, and 65537 bytes) exercise fragmentation. The corpus contains boundary-length frames followed by recovery markers, 128 generated byte runs containing embedded LF, CR, NUL and invalid UTF-8, and an unterminated final frame. Separate EOF cases verify empty input and lengths 65536 and 65537.

The executable `tools/adversarial_stdio_probe.py` adds 27 expected replies: padded valid ping frames at 65535, 65536 and 65537 total bytes with LF, CRLF, or EOF termination; following-ping recovery where a delimiter exists; and six malformed UTF-8/raw-control cases each followed by a valid ping. Invalid frames must produce fixed parse/size errors without reflecting their contents. The 64 KiB cap counts LF/CRLF bytes. EOF adds no delimiter. CI and the candidate packaging gate run this probe against debug and freshly installed optimized binaries.

Local debug replay passed on 2026-10-21. This is deterministic boundary and byte-preservation evidence, not coverage-guided fuzzing, proof for every byte stream, an indefinite-stream CPU/time limit, or a guarantee against stdout backpressure. No production behavior or runtime dependency changed in this milestone.


## Inspector era selection and fallback

The official Inspector 2.5.0 accepts `protocolEra` as a per-server configuration field. Its CLI parser allows unknown options and ignores `--protocol-era`; earlier smoke tests passed using the Inspector default rather than proving an explicit era selection. The runner now writes a temporary read-only `mcp.json` with the executable, explicit environment and era. It does not modify the user's catalog, and removes the temporary file afterward. Hostnames are operator/test configuration; no credentials are added.

The existing checks now select legacy explicitly. Additional `auto` invocations verify negotiation returns 2025-06-18, strict tool/schema discovery, a structured loopback denial and audit-resource access. Pinned `modern` must instead exit 1 with a negotiation diagnostic naming 2026-07-28 and no fallback; it must not return a tool listing. That negative case guards against an ignored era selector. A separate invalid-host configuration must fail startup rather than return tools, verifying the child environment is actually applied. Each invocation uses a fresh server, so its independent audit read is empty. These are Inspector CLI checks, separate from the 1,929-decision controlled network corpus.

This follows the newer revision's [stdio discovery/fallback model](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio#backward-compatibility). Automatic fallback is compatibility with a legacy server, not implementation of the modern revision. Full modern protocol support and other client/version tests remain open gates. CI and fresh optimized candidate packaging both run these checks; no dependency or server behavior changed.


## Partial-frame ingestion deadline

A frame has a 10-second wall-clock ingestion budget starting when the reader sees its first bytes, including time draining an oversized frame. The reader checks every chunk and completion; the dispatcher checks stalled partial input every 100 ms while waiting. An expired frame terminates the process with a fixed diagnostic, without dispatching or reflecting partial input. Idle input before the first byte has no deadline. Completed frames waiting on the rendezvous channel do not consume ingestion time. An executing fetch or blocked stdout write can delay dispatcher observation; replies have a separate three-second output deadline, described below. This is not a CPU quota.

The Linux resource probe now concurrently holds short and oversized partial frames open, verifies nonzero exit and redacted diagnostics within 13 seconds, and verifies a third idle client survives and accepts a ping afterward. A deterministic Rust regression checks already-expired frames at newline, data and EOF completion. Debug CI and installed optimized candidate packaging run the resource probe. Existing fast 160 MiB drain/recovery and 8 MiB EOF cases remain covered. No runtime dependency was added.


## Continuous-stream deadline regression

The resource probe also runs a fourth server while the other deadline cases execute. A controlled writer sends about 4 KiB every 20 ms without LF, keeping the stream active past the 64 KiB frame cap. The server must still terminate within the same 13-second test tolerance, with a fixed timeout diagnostic, no stdout, and no marker echo. Successful incoming bytes must not renew the ten-second ingestion budget. The nonblocking writer uses a stop event and bounded join so a failing server cannot trap the harness in a pipe write. This is finite Linux process evidence, not a CPU quota; output backpressure is tested separately below. Debug CI and the installed optimized candidate both run it.


## Reply output deadline

The stdio server uses one output worker and waits for each response's write/flush acknowledgement before sending another response. The three-second budget includes serialization, writing and flush; expiry terminates the process with a fixed `Output write deadline exceeded` diagnostic. The queue holds at most one response. The worker is not forcibly interrupted; process termination closes its pipe. The client may receive bytes of an incomplete JSON frame already written before termination and must discard them and reconnect. This applies to stdio replies, not help/version/configuration output or library calls. It is a conservative availability limit: a legitimate client that stops draining output for three seconds can be disconnected.

The Linux resource probe shrinks the child's stdout pipe to 4 KiB, sends a valid ping with a roughly 21 KiB string ID and deliberately reads no stdout until the child exits. It requires nonzero exit within six seconds, the fixed diagnostic with no full marker echo on stderr, and only an incomplete frame of at most 4 KiB on stdout. Normal reading and complete large-ID replies are covered by the existing framing corpus. Debug CI and freshly extracted optimized candidates run both probes. No runtime dependency was added. This bounds the tested blocked reply, not execution time of every OS operation or CPU usage.
