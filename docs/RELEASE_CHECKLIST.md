# Exact-candidate release evidence

Status: experimental; no official pre-1.0 release candidate or stable release approved. [Tracking issue #65](https://github.com/rhamenator/outbound-guard-mcp/issues/65) is the durable owner decision record. [QUALITY_BAR.md](QUALITY_BAR.md) remains authoritative; this index does not waive or narrow its criteria.

The [repeated installed SDK overload replay](evidence/installed-sdk-repeat-overload-2026-11-06.json) adds twelve consecutive client-generated busy, cancellation and recovery cycles under process and container limits. This is finite experimental Debian evidence; it does not satisfy the final client, platform, adversarial or owner-acceptance gates below.

The [installed SDK host-budget replay](evidence/installed-sdk-rate-budget-2026-11-06.json) adds a client-generated 60/61 per-host rate-boundary check against an experimental package built from trusted main. The denied call opened no DNS/HTTP path, and the server remained responsive. Final candidate, multi-process, reset-window, other-client and owner gates remain open.

The [installed SDK failed-DNS budget replay](evidence/installed-sdk-dns-failure-budget-2026-11-06.json) adds a second 60/61 boundary: failed lookups consume their hostname's rate slots, and the next SDK call is denied before DNS or HTTP. This is finite experimental Debian evidence; the release and owner gates remain open.

The [installed SDK audit-retention replay](evidence/installed-sdk-audit-retention-2026-11-06.json) drives 302 guarded decisions in one process and checks that the audit resource retains only the newest 256, in order, without URLs or body text. The server remains responsive after the controlled DNS failures. General resource bounds and the exact-candidate gate remain open.

The [installed SDK rate-window reset replay](evidence/installed-sdk-rate-reset-2026-11-06.json) extends that same-process sequence past the per-host minute window. Both the previously exhausted allowed host and failed-DNS host receive fresh reservations after 61 seconds; controlled DNS and the approved HTTP path resume, while the audit stays capped at 256 events. This finite timing check does not qualify the exact candidate or establish cross-process budgets.

The [installed SDK process-hour budget replay](evidence/installed-sdk-hour-budget-2026-11-06.json) drives 1,000 reserved guarded calls through the official SDK in one process. The 1,001st call to a fresh operator-allowed hostname returns `EGRESS_RATE_LIMIT` before DNS or HTTP; the audit remains bounded and discovery responds. This finite experimental Debian result does not prove an hourly reset, cross-process quotas, arbitrary concurrency, or release readiness.

The [installed SDK hour-fill resource replay](evidence/installed-sdk-hour-resource-2026-11-06.json) samples server file descriptors during the 698-call DNS failure fill and reads server/process and container high-water counters afterward. Two finite installed-package runs stayed within their 64-FD, 64-PID and 128 MiB limits without OOM. Sampling can miss transient FD peaks; this does not establish a general resource bound or release approval.

The [installed SDK audit-result linkage replay](evidence/installed-sdk-audit-linkage-2026-11-06.json) matches the retained 256 audit events to the SDK's own structured decisions across a 699-decision pressure phase, checking consecutive unique correlation IDs and exact status/rule agreement. This finite sequential check does not establish concurrent audit ordering, broad client behavior, or release approval.

The [installed SDK concurrent-denial audit replay](evidence/installed-sdk-concurrent-denial-audit-2026-11-06.json) submits 16 guarded calls together after the process-hour cap. Two installed-package runs accepted 13/9 rate-limit decisions and rejected 3/7 at the bounded input gate; accepted results matched their audit events, and a serial call recovered. No new DNS or HTTP occurred. This finite submission burst does not establish overlapping server execution, general concurrency bounds or release approval.

The [Debian upgrade operator-policy replay](evidence/debian-upgrade-operator-policy-2026-11-06.json) compares the same explicit allowlist on changed-binary experimental packages 205 and 242 before and after `dpkg` upgrade. Two disposable network-disabled Debian 12 amd64 runs matched structured allowlist/DNS-denial decisions and redacted audit, then passed removal and residue checks. This validates one environment-setting compatibility path, not saved configuration migration, same-container native-client upgrade behavior, or exact-candidate approval.
