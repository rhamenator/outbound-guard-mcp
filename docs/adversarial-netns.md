# Isolated socket probe

`bash tools/netns_adversarial_probe.sh target/debug/outbound-guard-mcp` runs the built MCP server against DNS, HTTP, and TLS fixtures inside a disposable Linux network namespace. The namespace has no external route. Its only approved address, `11.0.0.1`, is assigned to its own loopback interface; the host's DNS and firewall configuration are untouched. The script needs `sudo -n`, `iproute2`, Python 3, and OpenSSL to create an ephemeral test certificate. It removes the namespace, private resolver configuration, and certificate on exit.

The probe sends actual MCP `tools/call` requests. Private-only and mixed public/private DNS answers must produce `EGRESS_FORBIDDEN_ADDRESS` with zero HTTP requests. The expanded DNS matrix also includes link-local metadata (`169.254.169.254`), carrier-grade NAT (`100.64.0.1`), IPv4 documentation space, IPv6 loopback, IPv4-mapped loopback, unique-local IPv6, IPv6 documentation and transition prefixes, and a mixed public A/private AAAA answer. Every one must be denied before any HTTP connection. A 20-address DNS answer must return `EGRESS_DNS_ANSWER_LIMIT` with no HTTP hit. Six synthetic URL secret markers (AWS long-term and temporary key shapes, two GitHub token shapes, an API key shape, and a high-entropy path) must be denied before DNS or HTTP, without appearing anywhere in the MCP output or stderr. An approved hostname must return its plain-text response even when `HTTP_PROXY` and `ALL_PROXY` (including lowercase variants) point to a dead local proxy. A TLS fixture on the pinned address records SNI `allowed.test`; its ephemeral certificate is issued to `wrong.test`, and the guarded call must fail before an HTTP request is served. Redirect, gzip-encoded, and declared oversized responses must produce their respective denial codes. Additional 307 responses point to themselves or to another approved hostname; neither may trigger a follow-up HTTP request, and the cross-host case must not resolve the destination. Gzip and deflate fixtures each compress 8 MiB of text below 16 KiB; both must return `EGRESS_ENCODED_RESPONSE` without body text. An HTML fixture with a CSS-hidden link and a misleading `text/plaintext` media type must both be denied as `EGRESS_UNSUPPORTED_CONTENT`. The same hidden-link fragment declared `text/plain` and a form-feed-delimited `<script>` tag must be denied as `EGRESS_HTML_MISLABELED`, while ordinary prose containing `<html>` must remain readable. JSON fixtures containing mislabeled HTML, a truncated object, trailing garbage, 200 nested arrays, and an empty 200 body must return `EGRESS_INVALID_JSON` without body text. A 204 response remains accepted with an empty body. A valid JSON HTML string, a numeric value `1e400` beyond finite double range, and an instruction-like object remain returned with `untrusted_content: true`, proving syntax validation and the marker but not sanitization. Conflicting Content-Length/Transfer-Encoding and duplicate Content-Length responses must fail closed; stacked `gzip, chunked` and duplicate `chunked` transfer-coding fields must return `EGRESS_UNSUPPORTED_TRANSFER_CODING` without body text; reqwest may reject either during parsing as `EGRESS_NETWORK_FAILURE` before the guard can emit `EGRESS_INVALID_FRAMING`. Duplicate Content-Type and Content-Encoding response fields must return `EGRESS_AMBIGUOUS_RESPONSE_METADATA` without body text. A chunked response with no declared length must hit the byte cap. Invalid chunk-size syntax and a truncated chunk after one complete chunk must fail closed as `EGRESS_READ_FAILURE` or an earlier parser failure, without returning the already buffered text. Responses with 70 headers or a 24 KiB header must produce `EGRESS_RESPONSE_HEADERS_LIMIT`. A 1 MiB header must fail in the HTTP parser as `EGRESS_NETWORK_FAILURE` before the guard receives it. A rebinding fixture changes its A answer from the isolated public address to loopback after the first lookup. The first direct fetch succeeds; a second call in the same MCP server process must query DNS again, deny the loopback answer, and open no further HTTP socket. Delayed headers, a one-byte-per-second body, and EOF just after the total deadline must fail within 16 seconds, without a partial body in the result. The body cases guard against a per-read timeout being reset by every arriving byte and late EOF being accepted as safe. CI runs the same fixture after building the binary.

This is socket-level evidence for sixty-one hostile-response cases and three budget probes (1,123 repeated-call decisions), not a full adversarial certification. The 20-answer probe proves the application rejects the oversized pinned set; it does not bound memory allocated internally by the OS resolver. The rebinding run proves a second call in the same server process denies a changed DNS answer; it does not exercise a reconnect within one call or every resolver-cache behavior. The redirect probes prove the current all-redirect denial policy, not safe multi-hop revalidation. The HTML signature check only examines leading markup in `text/plain`; content with a prose prefix or an unrecognized tag can still pass, and an agent may still follow instructions in JSON despite the untrusted marker. Content scrubbing and robust prompt-injection handling remain open gates. The slow-drip denial proves a total response deadline, not a sliding byte-rate detector. The secret probe covers five known-token shapes and one entropy example in a URL. It does not prove detection of arbitrary secrets or request header/body exfiltration; this tool currently rejects custom headers and bodies. A PEM private-key marker cannot be carried in a raw URL because whitespace is rejected first. The original untrusted wrong-host certificate remains a combined trust/hostname rejection case. The additional operator-CA fixture isolates hostname verification: a trusted matching SAN succeeds and a same-issuer mismatched SAN fails before HTTP. A matching SAN without the configured CA also fails. This covers this certificate chain, not every TLS configuration. The gzip/deflate tests prove explicit coding denial for those two bombs, not all encodings or mislabeled data. Malformed framing coverage includes those two header conflicts plus invalid and truncated chunked bodies; it is still a finite parser sample. The header count and byte limits apply after reqwest parses the response. The pinned Hyper HTTP/1 parser currently has a default read buffer ceiling of 417,792 bytes, and the 1 MiB fixture checks that it fails closed; Outbound Guard does not configure that ceiling itself, so dependency updates require retesting. This is not a complete parser memory or concurrency bound. Other decompression paths, concurrent resource exhaustion, and real-client use remain release gates in [QUALITY_BAR.md](QUALITY_BAR.md). It also cannot govern traffic an agent sends through other tools.

## Live budget evidence

Each budget probe starts one fresh MCP server process and runs all its calls in that process. The per-host probe alternates hostname casing and mixes 30 valid responses with 30 malformed JSON responses; call 61 must return `EGRESS_RATE_LIMIT`. A separate probe performs 60 failed DNS lookups; call 61 must be rate-limited without another lookup. The hourly probe spreads 1,000 successful fetches over 17 approved fixture hosts (each below the per-host limit), then requires call 1,001 to be denied. Fixture A/AAAA-query and HTTP-hit counts prove no extra DNS or HTTP activity for the blocked call. The audit resource must retain exactly the latest 256 completed decisions, including budget denials. These are sequential stdio tests; concurrent clients, multiple processes, and expiry of real minute/hour windows remain unproven by this fixture. Time-window arithmetic is covered separately by unit tests. No external target is contacted.

## Operator CA and hostname verification

The probe creates an ephemeral CA and two server certificates signed by it, with SANs `allowed.test` and `wrong.test`. With `OUTBOUND_GUARD_EXTRA_CA_CERT` set to that CA certificate, the matching SAN must produce `EGRESS_ALLOWED`; the mismatched SAN must produce `EGRESS_NETWORK_FAILURE` without any HTTP hit or returned body. The matching certificate must also fail when the CA option is absent. SNI is observed as `allowed.test`. Ten startup probes cover an empty path, missing file, directory, FIFO, private key, empty file, invalid text, an oversized file, malformed certificate DER, and multiple certificates. They must exit without MCP output, network traffic, or content/path echo. Temporary certificates and private keys are removed after the probe. The production trust option reads only the operator-designated regular file, once at startup, with a 64 KiB read cap; it is not a tool argument.

A synthetic AWS-shaped marker in rejected arguments must not appear in results, stderr, or the bounded audit snapshot. The final log verifies audit correlation and last-256 retention after the generated calls.

The pre-fix binary accepted a leading NUL after the URL parser silently removed it (seed `306373022276`, initial corpus index 545). The server now rejects all raw ASCII control bytes before URL parsing, budget reservation, or DNS. A unit test also covers all 99 byte/position combinations. The runner prints a corpus SHA-256 for exact replay identification. These add 645 guarded calls to the 1,184 core/budget decisions: 1,829 decisions before the additional GitHub corpus below, rather than 1,829 distinct attack types. The same probe runs against debug and installed optimized candidate builds. Broader grammar, coverage-guided, framing, and IP fuzzing remain open.

## Repeated-call descriptor and memory evidence

The three live-budget processes now run under `prlimit --nofile=64:64` (Linux util-linux), with the applied child limit checked through `/proc/PID/limits`. The harness samples `/proc/PID/fd` and the kernel RSS high-water mark (`VmHWM`) about every 5 ms while communicating with the child. Each process must complete under the OS-enforced 64-descriptor limit, with sampled RSS high-water below 128 MiB and at least two observed samples. CI and installed optimized candidate checks run the same probe.

The workloads retain their existing assertions: 30 successful and 30 malformed-JSON fetches then a per-host denial; 60 failed DNS lookups then a denial; and 1,000 successful fetches across 17 hosts then an hourly denial. Replies, exact DNS/HTTP counts, and bounded redacted audit retention must still match. This exposes descriptor leaks or memory growth large enough to break these finite workloads. It does not measure every transient descriptor count (the OS limit enforces that cap), impose a production RSS cap, prove indefinite soak behavior, or coordinate multiple server processes. The cap is applied by the test harness, not a new server configuration. No additional tool decisions or external network targets are added.

## Cooperative library cancellation

Build the server and its controlled library consumer with `cargo build --locked --bins --examples`, then run the namespace probe as before. The shell runner defaults the consumer to `target/debug/examples/cancel_fetch_probe` beside the server binary’s target directory; an explicit second argument can select another consumer binary. Candidate packaging builds both from the committed source snapshot and passes the optimized consumer explicitly. The example is included as source, not as an additional distributed server executable.

The HTTP fixture streams one byte per second. After it flushes the first byte and a 150 ms settling period, the harness signals the library consumer over stdin. The consumer sets its shared atomic cancellation flag. The call must finish within five seconds of that signal with audited `EGRESS_CANCELLED` and no `body_text`; the fixture must observe the connection close while the consumer process remains alive. A fresh normal fetch in the same process must then succeed, proving the active-fetch permit was released. This adds two direct library decisions to the MCP tool decisions; they are not MCP cancellation tests. A Rust unit test covers pre-cancelled calls without rate-budget consumption.

Cancellation is cooperative: it is checked before reservation/network work, after DNS/request completion, around body reads, and before returning successful text. A pending blocking operation is not forcibly interrupted, and a timed-out OS resolver worker may continue. Cancellation can race completion, and reservations already consumed remain counted. This fixture covers plaintext streaming cancellation, not every DNS, TLS, idle/read timing, or client behavior. Stdio cancellation is tested separately below; complete cancellation and newer-protocol conformance remain release gates.

## Stdio cancellation

A bounded stdin-reader thread now recognizes the implemented 2025-06-18 [cancellation notification](https://modelcontextprotocol.io/specification/2025-06-18/basic/utilities/cancellation) while the dispatcher executes one fetch. It registers only tool requests, before handing their frame to the dispatcher, so an immediate notification can set the same cancellation flag. Completed entries are removed by flag identity. String and integer IDs match exactly. Malformed, unknown and completed cancellations are ignored, initialization is not cancellable, and cancellation reasons are never logged or echoed. When the library returns `EGRESS_CANCELLED`, the dispatcher suppresses the RPC reply while retaining the redacted audit decision.

Two fresh-process wire cases cancel a slow response after its first byte, using string and integer IDs. Wrong-ID-type, initialize-ID, malformed-reason and malformed-metadata notifications must leave the socket open. A valid matching notification must yield no cancelled-call reply, allow a subsequent ping, close the peer socket while the server stays alive, and record one redacted cancellation. A late/duplicate notification must not prevent a normal fetch reusing the completed request ID. A request-shaped cancellation with its own ID must get a method error. The cases add four MCP tool decisions (1,854 total), alongside the two separate library decisions.

The current reader uses eight admitted frames and a separate bounded queue of eight busy replies. Ordinary admission never blocks cancellation scanning; excess requests receive `MCP_INPUT_BUSY`, and exhausting both queues closes the connection and cancels admitted fetches. EOF drains admitted work. The [priority and overload evidence](cancellation-priority.md) supersedes the earlier read-ahead-only saturation limitation. Fetch execution remains sequential and cancellation cooperative; spent reservations are not refunded. Normal corpora now pace requests and preserve every case without retrying or suppressing busy errors; dedicated concurrent probes test overload.


## Official SDK AbortSignal

To include the development-only official TypeScript SDK test, install its exact dependency graph from the committed npm lockfile before entering the route-free namespace:

```sh
npm ci --prefix tools/mcp-sdk-probe --ignore-scripts --no-audit --no-fund
export OUTBOUND_GUARD_TEST_SDK_DIR="$PWD/tools/mcp-sdk-probe"
bash tools/netns_adversarial_probe.sh target/debug/outbound-guard-mcp
```

Node.js 18 or newer and npm are required for this optional local probe. CI requires it for both the debug executable and freshly installed optimized candidate. Acquisition contacts the npm registry outside the isolated fixture; no registry access occurs inside the namespace. These are test dependencies, not server dependencies, and no npm installation is needed to run the Rust server or skill. The source archive carries the test manifest and lockfile; node_modules and SDK executables are not distributed in the server archive.

The SDK 1.32.1 Client and StdioClientTransport perform the handshake and a real guarded fetch. After the fixture observes its first response byte, the harness instructs the client to abort its AbortController. The SDK must reject the local promise and send its own cancellation notification. A subsequent SDK ping acts as a server completion barrier, and resources/read must show exactly one EGRESS_CANCELLED audit event. A normal fetch then succeeds. The fixture verifies the cancelled peer socket closed while the SDK/server remain alive, checks exactly two HTTP requests, and requires the sequence to complete within five seconds of abort. This adds two MCP decisions (1,856 total with this probe enabled), alongside two direct library decisions. Without the environment variable, the runner explicitly reports this probe was not requested.

This covers one official SDK version over stdio during plaintext response streaming. It does not close the separate Cursor/Codex/Claude UI abort gate, all cancellation timing phases, or newer protocol conformance. Existing wire tests separately check exact ID matching, malformed notifications, reply suppression, and reason redaction.

Local replay on 2026-10-21 passed against the debug build: SDK abort/audit/recovery completed in 1.02 seconds, all 1,856 MCP decisions plus two library decisions passed, and the three budget subprocesses stayed at or below seven sampled descriptors and 11,056 KiB VmHWM under a 64-FD hard limit. These are bounded fixture observations, not general production memory or latency guarantees.

## Structured decision schema

The official SDK probe now discovers guarded_fetch.outputSchema and validates a real allowed fetch and an additional blocked loopback call (no extra HTTP hit). The SDK validator also rejects nine synthetic mutations: body or URL in a denial, contradictory rule/status, false untrusted-content marker, invalid HTTP status, malformed correlation ID, null/missing body and unknown fields. A synthetic audit failure without correlation ID must remain valid. This adds one MCP decision, for 1,857 when the SDK probe is enabled; prior recorded counts remain historical. The schema describes current results rather than adding content trust. HTTP status codes up to 999 reflect the HTTP library’s accepted range; SAFE is independent of HTTP success. Normalized URL length can exceed the input length after percent encoding, so the result schema does not reuse the input length limit. No server runtime dependencies were added.

## Rolling response-rate floor

The body reader now uses four fixed one-second counters: current partial second and three completed seconds. After a three-second body grace period, fewer than 1,500 bytes in the completed buckets produces audited EGRESS_RESPONSE_TOO_SLOW with no partial text. An initial burst expires from the window. State does not grow with read/chunk count. Checks run after successful reads (including EOF), with existing blocking-read/idle-time limitations; read errors retain their original rules. Fast small responses finish during grace. The policy may reject legitimate slow responses and is not suitable for subscriptions.

The controlled one-byte/second fixture must now receive the rate denial within seven seconds rather than waiting for the ten-second deadline. A new 2,000-byte burst followed by one-byte/second fixture must also be denied within seven seconds; a 2,400-byte response delivered as 600 bytes/second must succeed. The late-EOF fixture now sends 600 bytes/second to test the independent total deadline without triggering the rate floor. These add two guarded decisions (1,859 with the SDK probe enabled, plus two separate library decisions). Rust unit tests check grace, exact 499/500/501-byte thresholds, burst expiry and large time gaps without sleeping. No dependencies were added.

## UTF-8 Content-Type parameters

GET accepts only `text/plain` or `application/json`, without parameters or with one `charset=utf-8` declaration (case insensitive, optionally double quoted). Unknown parameters, duplicate declarations, conflicting charsets and malformed declarations are rejected as `EGRESS_UNSUPPORTED_CONTENT` before body text is returned. This intentionally narrow policy does not guess encodings or implement a general MIME parser. Actual body bytes must still be valid UTF-8; HEAD retains its media-type exemption.

The route-free HTTP fixture adds ten actual MCP decisions: six rejected cases (ISO-8859-1, UTF-16, duplicate UTF-8, unknown profile, unmatched quote and empty parameter) and four accepted plain/JSON/quoted-case/whitespace controls. Rejected decisions contain no body marker; controls preserve the exact UTF-8 body with `untrusted_content:true`. The full corpus now has 1,967 MCP decisions plus two direct library cancellation calls when the official SDK fixture is enabled. These cases verify the configured policy, not every MIME grammar or encoding.


## Hard HTTP total deadline

The synchronous tool/library entry point now drives Reqwest async I/O on a current-thread Tokio runtime. An outer ten-second timeout covers HTTP client setup/connect/headers/body, and Reqwest enforces a three-second read timeout plus its own total timer. Dropping the expired future and runtime tears down the pending request; cancellation remains cooperative at the existing checks. DNS retains a separate three-second phase budget. These deadlines are subject to runtime/OS scheduling and do not form a ten-second whole-tool or CPU guarantee.

The late-EOF fixture now delivers 500 bytes every 250 ms for forty iterations, then delays closing a further 2.5 seconds. This keeps rate classification independent from the deadline under test. The test requires `EGRESS_RESPONSE_TIMEOUT`, no partial body, and completion within 11.5 seconds including process/fixture overhead. This distinguishes the total timer from the former between-read check, which could wait for the three-second idle timeout near twelve seconds. The independent 600 B/s control uses 120-byte writes every 200 ms and still succeeds. Granular writes avoid bunching at one-second bucket boundaries; the production rate threshold is unchanged. The full suite also rechecks TLS/pinning, slow-drip detection, cancellation peer closure, resource use and post-cancellation recovery.

This closes the tested pending-read total-deadline overrun, not all hard network-limit gates. At that milestone, header caps were still applied after dependency parsing and raw wire/pre-parse bounds remained work. The subsequent configured transport below supplies those bounds; library buffer allocations still do not constitute a process-wide memory quota. No new locked crate/package version is added; Tokio is promoted from an existing transitive dependency.


## Configured HTTP parser and stream budgets

The HTTP/1 transport now dials only validated addresses and uses Hyper directly over budgeted TCP/TLS streams. Rustls verifies the original hostname against built-in WebPKI roots plus the optional operator-owned CA; the prior trusted/mismatched/untrusted TLS fixtures still pass. There is no ambient proxy, credential, redirect or connection-pool lookup. One connection driver is aborted when its response scope ends; the outer total timeout also tears down the runtime.

Configured bounds are 64 parsed header fields, a 16 KiB parser buffer including status line, 4096 outbound HTTP bytes, response HTTP bytes of `max_return_bytes + 32 KiB`, and underlying TCP/TLS read/write budgets of 1 MiB/64 KiB. Stream counters sit before HTTP parsing and before TLS processing respectively; the HTTP counter sits after decryption. Request serialization is conservatively estimated with fixed overhead before budget reservation/DNS, with an I/O cap as defense in depth. HTTP body frames are checked before copying into the return buffer. Compression remains denied, so decompression/expansion is unsupported rather than silently unbounded. These limits exclude IP headers, retransmissions, kernel buffers, resolver allocations and CPU.

Six additional MCP decisions bring the full controlled corpus to 1,973 plus two library cancellation calls: an encoded Unicode path exceeding the serialized request budget (no DNS/HTTP), 20,000 one-byte chunks whose framing exceeds the HTTP budget despite a small decoded body, unsupported response trailers, and raw header blocks of 16,383/16,384/16,385 bytes. The first two header controls return `ok`; the over-limit header fails within parsing. Oversized/invalid heads now return `EGRESS_INVALID_FRAMING`; Hyper's client API does not publicly distinguish every parser size error, so tests require this deterministic general framing rule instead of claiming a precise cause. Other framing/metadata denials remain explicit where observable. Denials return no body.

The synchronous library API rejects invocation inside an already active Tokio runtime with `EGRESS_CLIENT_FAILURE` before validation/network work, avoiding nested-runtime panic. Async embeddings must use a blocking worker. A regression verifies this fail-closed behavior. Header/TLS buffers still belong to the maintained libraries; these stream budgets are not a process-wide memory quota. Remaining protocol/client/release acceptance criteria are not waived.

Independent in-memory duplex-stream regressions also verify that exhausted read budgets leave excess bytes unread and exhausted write budgets never emit excess bytes. The same budget wrapper is used around HTTP and underlying TCP/TLS streams. Oversized-header fixtures treat peer closure while writing headers as expected rejection; unrelated fixture exceptions remain visible.

## Live OS DNS worker exhaustion and recovery

The controlled namespace suite now exercises the real libc resolver path, not only the injected resolver unit test. In both modern stateless and legacy modes, the fixture withholds A/AAAA answers for one approved hostname while the private namespace's resolver timeout is six seconds. The server must return `EGRESS_DNS_TIMEOUT` at its separate three-second deadline with exactly one extra OS resolver thread still alive. Twenty subsequent calls alternate the stalled hostname and a different approved hostname; all must return `EGRESS_DNS_BUSY`, preserve that single extra thread, and create no additional DNS question or HTTP request. Sampled RSS must stay below 64 MiB and descriptors below 32.

The fixture then releases the withheld DNS replies. The worker must disappear within two seconds, without an HTTP request from the expired call. A fresh approved request must succeed and produce the only new HTTP hit. The redacted audit must contain exactly one timeout, twenty busy denials and one allow. Both eras add 44 decisions to the socket corpus (2,021 total). The first debug replay measured timeout 3.00 seconds, one held worker, four descriptors and RSS below 9 MiB; record the exact candidate/CI values with release evidence. These are finite observations, not OS-wide allocator/thread/CPU guarantees or coverage of every libc/NSS implementation.

The test changes only the launcher's disposable `/etc/netns/outbound-guard-probe-<pid>/resolv.conf` file, after verifying it is the inode bind-mounted at `/etc/resolv.conf` inside that namespace. It refuses to proceed without the expected launcher name and private mount. The original resolver file is restored in a `finally` block, all waiting DNS handlers are released on error, child processes are reaped, and launcher cleanup removes the namespace and its resolver file. It never changes the host's resolver configuration. The fixture's delayed response handlers have their own eight-second bound.

Operational boundary: timing out a tool call does not forcibly interrupt portable `getaddrinfo`. A process with a still-running lookup denies DNS work for **all** hosts until that worker exits; repeated calls do not replace the worker. Already spent request budgets remain counted, including busy denials. Wait before retrying; do not bypass policy through another tool. This proves bounded lingering-worker behavior for the exercised DNS stall, not prompt cancellation of NSS plugins, unbounded OS answer allocation or service availability when the OS resolver never returns.

### Cooperative DNS waiter cancellation

The same private resolver-stall fixture also cancels an active libc lookup in both protocol eras. It waits until the DNS query arrives, sends `notifications/cancelled`, and requires a following ping within one second with no cancelled tool reply. The audit must record `EGRESS_CANCELLED`. Twenty further requests must fail with `EGRESS_DNS_BUSY` while exactly one native worker remains, without additional DNS or HTTP. Releasing the fixture must discard the late answer and allow a fresh request.

The waiter polls the cancellation flag every 25 ms, retaining the original three-second absolute DNS deadline. This is cooperative observation subject to scheduling, not an OS thread interrupt. The native resolver retains its gate until it actually exits. The suite now exercises 2,065 MCP decisions; this finite Linux fixture does not prove every NSS backend or client cancellation path.

### Cancellation during silent HTTP waits

The controlled HTTP fixture accepts a request and then either sends no headers or sends valid text headers followed by no body bytes. In both legacy and modern protocol modes, it signals that the request reached the server before the client sends cancellation. The probe requires a following ping and observed peer socket closure within one second, no cancelled tool reply, a sole `EGRESS_CANCELLED` audit event, and successful reuse of the cancelled request ID for a fresh GET. These eight additional tool decisions bring the corpus to 2,073.

The HTTP driver retains a single pinned ten-second total-deadline future and waits on it in 25 ms slices. Cancellation drops the future and runtime, releasing the socket even when no next response byte arrives. Slices do not restart the total deadline; existing delayed/streaming timeout fixtures still apply. Timing is cooperative and subject to scheduling. This fixture covers silent plaintext header/body waits; it does not certify every OS connect/TLS state or native client UI control.

### Post-DNS syscall observation

The controlled network suite now traces a live server with `strace -f -yy -e trace=network` in each protocol era. Eight subsequent calls resolve loopback, mixed public/private, metadata link-local, carrier-grade NAT, documentation and IPv6 forbidden answers through the actual OS resolver. The trace must contain exactly two TCP connects per era, both to the approved fixture address on port80.
