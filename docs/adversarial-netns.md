# Isolated socket probe

`bash tools/netns_adversarial_probe.sh target/debug/outbound-guard-mcp` runs the built MCP server against DNS, HTTP, and TLS fixtures inside a disposable Linux network namespace. The namespace has no external route. Its only approved address, `11.0.0.1`, is assigned to its own loopback interface; the host's DNS and firewall configuration are untouched. The script needs `sudo -n`, `iproute2`, Python 3, and OpenSSL to create an ephemeral test certificate. It removes the namespace, private resolver configuration, and certificate on exit.

The probe sends actual MCP `tools/call` requests. Private-only and mixed public/private DNS answers must produce `EGRESS_FORBIDDEN_ADDRESS` with zero HTTP requests. The expanded DNS matrix also includes link-local metadata (`169.254.169.254`), carrier-grade NAT (`100.64.0.1`), IPv4 documentation space, IPv6 loopback, IPv4-mapped loopback, unique-local IPv6, IPv6 documentation and transition prefixes, and a mixed public A/private AAAA answer. Every one must be denied before any HTTP connection. A synthetic AWS-shaped token in the URL must be denied before DNS or HTTP, without appearing in the result. An approved hostname must return its plain-text response even when `HTTP_PROXY` and `ALL_PROXY` (including lowercase variants) point to a dead local proxy. A TLS fixture on the pinned address records SNI `allowed.test`; its ephemeral certificate is issued to `wrong.test`, and the guarded call must fail before an HTTP request is served. Redirect, gzip-encoded, and declared oversized responses must produce their respective denial codes. Additional 307 responses point to themselves or to another approved hostname; neither may trigger a follow-up HTTP request, and the cross-host case must not resolve the destination. Gzip and deflate fixtures each compress 8 MiB of text below 16 KiB; both must return `EGRESS_ENCODED_RESPONSE` without body text. An HTML fixture with a CSS-hidden link and a misleading `text/plaintext` media type must both be denied as `EGRESS_UNSUPPORTED_CONTENT`. A JSON fixture with an instruction-like string remains returned with `untrusted_content: true`, proving the marker but not sanitization. Conflicting Content-Length/Transfer-Encoding and duplicate Content-Length responses must fail closed; reqwest may reject either during parsing as `EGRESS_NETWORK_FAILURE` before the guard can emit `EGRESS_INVALID_FRAMING`. A chunked response with no declared length must hit the byte cap. Responses with 70 headers or a 24 KiB header must produce `EGRESS_RESPONSE_HEADERS_LIMIT`. A 1 MiB header must fail in the HTTP parser as `EGRESS_NETWORK_FAILURE` before the guard receives it. A rebinding fixture changes its A answer from the isolated public address to loopback after the first lookup. The first direct fetch succeeds; a second call in the same MCP server process must query DNS again, deny the loopback answer, and open no further HTTP socket. Delayed headers, a one-byte-per-second body, and EOF just after the total deadline must fail within 16 seconds, without a partial body in the result. The body cases guard against a per-read timeout being reset by every arriving byte and late EOF being accepted as safe. CI runs the same fixture after building the binary.

This is socket-level evidence for these thirty-five cases, not a full adversarial certification. The rebinding run proves a second call in the same server process denies a changed DNS answer; it does not exercise a reconnect within one call or every resolver-cache behavior. The redirect probes prove the current all-redirect denial policy, not safe multi-hop revalidation. The HTML check relies on the server-declared media type; HTML mislabeled as `text/plain` can still pass, and an agent may still follow instructions in JSON despite the untrusted marker. Content scrubbing and robust prompt-injection handling remain open gates. The slow-drip denial proves a total response deadline, not a sliding byte-rate detector. The secret probe covers one known-token pattern in a URL, not arbitrary exfiltration. The TLS certificate is both for a different hostname and untrusted, so this test proves SNI preservation and TLS fail-closed behavior but does not isolate hostname mismatch as the reason. The gzip/deflate tests prove explicit coding denial for those two bombs, not all encodings or mislabeled data. Malformed framing coverage is limited to the two header conflicts above. The header count and byte limits apply after reqwest parses the response. The pinned Hyper HTTP/1 parser currently has a default read buffer ceiling of 417,792 bytes, and the 1 MiB fixture checks that it fails closed; Outbound Guard does not configure that ceiling itself, so dependency updates require retesting. This is not a complete parser memory or concurrency bound. Other decompression paths, a trusted-certificate hostname-mismatch case, concurrent resource exhaustion, and real-client use remain release gates in [QUALITY_BAR.md](QUALITY_BAR.md). It also cannot govern traffic an agent sends through other tools.
